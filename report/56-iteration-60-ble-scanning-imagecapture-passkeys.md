# Iteration 60: Bluetooth Low Energy Scanning, W3C MediaCapture Image Optical Governance & FIDO2/WebAuthn Passkeys Architecture

## Overview & Executive Summary

Milestone 60 integrates three foundational web platform, hardware sensor, and cryptographic authentication specifications into the Super-App Mini-App Store Standard:
1. **Bluetooth Low Energy Scanning API & Advertisement Processing (Web Bluetooth Scanning)**: Standardizes passive radio observation via `navigator.bluetooth.requestLEScan()` with declarative 16-bit/128-bit service UUID and `manufacturerData` company identifier filters. Implements `BluetoothAdvertisingEvent` payload parsing (`rssi`, `txPower`, `serviceData`, `manufacturerData` DataViews). Establishes log-distance path loss proximity formulas with host-mediated Kalman filtering and hysteresis thresholds to counteract multi-path interference. Enforces battery preservation rules by clamping scan duty cycles and suspending background radios upon page visibility loss. Neutralizes physical tracking through ephemeral, origin-scoped device identifiers and complete IEEE MAC address masking.
2. **W3C MediaCapture Image API & High-Resolution Optical Governance**: Decouples full-sensor still photo capture from preview video viewfinders via `new ImageCapture(videoTrack)`. Standardizes `takePhoto()` with granular `PhotoSettings` (`imageWidth`, `imageHeight`, `fillLightMode`), accompanied by container-enforced RAM buffer ceilings (rejecting captures if available memory <150MB) and automated EXIF PII sanitization. Introduces `grabFrame()` for low-latency, zero-copy `ImageBitmap` extraction directly transferred to Dedicated Web Workers for off-thread computer vision (CV). Exposes sensor telemetry and validated boundaries via `getPhotoCapabilities()` and `MediaSettingsRange`. Establishes strict store criteria for financial optical eKYC, mandating native document bounding stencils, sharpness validation, and in-memory WebCrypto AES-GCM-256 encryption.
3. **FIDO2 / WebAuthn Passkeys Architecture & Relying Party Cryptographic Governance**: Formalizes multi-device discoverable credentials (Passkeys) synchronized across user devices via end-to-end encrypted keychains (Apple iCloud Keychain, Google Password Manager). Details the anti-phishing mathematical guarantees of `clientDataJSON` (cryptographic binding of `challenge`, `origin`, and `rp.id`). Analyzes FIDO CTAP 2.0/2.1 client-to-authenticator communication framing over CBOR and user verification via the `pinUvAuthToken` ECDH protocol, shielding raw biometrics inside hardware Secure Enclaves / StrongBox Keymasters. Standardizes Passkey Conditional UI (`mediation: conditional` + HTML `autocomplete="username webauthn"`) for zero-friction form autofill. Establishes super-app multi-tenant passkey delegation architectures where the super-app root RP authenticates users natively and exchanges down-scoped, audience-restricted OAuth/OIDC tokens with third-party micro-apps.

## Technical Deep Dive: Specifications & Implementation Guidance

### 1. Web Bluetooth Scanning API: Low-Power Beacon Observation & Anti-Tracking
The Web Bluetooth Scanning API allows web applications in secure contexts to receive passive advertising packets from nearby BLE peripherals without establishing full GATT connections.
- **Request Semantics & Permissions Policy**: Invoked via `navigator.bluetooth.requestLEScan(options)`. Standard mini-apps must provide targeted filters (`services`, `namePrefix`, or `manufacturerData`); wildcards (`acceptAllAdvertisements: true`) are rejected by store policies. Requires explicit user permission and activation under the `bluetooth` Permissions Policy.
- **Payload Parsing (`BluetoothAdvertisingEvent`)**: Dispatched to `navigator.bluetooth` upon receiving a matching advertising packet. Exposes:
  - `device`: Origin-scoped handle with an ephemeral unique ID.
  - `rssi` and `txPower`: Signal strength indicators in dBm used for proximity calculation.
  - `manufacturerData`: Map linking 16-bit company identifiers (e.g. Apple 0x004C, Nordic 0x0059) to raw binary `DataView` payloads.
  - `serviceData`: Map linking 16-bit or 128-bit UUID strings to data buffers.
- **Proximity Estimation & Jitter Smoothing**: Distance is calculated using the log-distance path loss model: $\text{Distance} = 10^{(\text{txPower} - \text{RSSI}) / (10 \cdot n)}$. Due to environmental noise, the host container executes native Kalman filtering across successive packets before triggering proximity business events (e.g. smart shelf promotions), enforcing entering/exiting hysteresis bands.
- **Hardware Power & Duty Cycle Arbitration**: To prevent rapid battery drain (up to 15%/hour under 100% duty cycle), the super-app sets default scanning to low duty cycles (10% duty cycle: 50ms window / 500ms interval). Continuous high-duty scans are clamped to 30 seconds max. Backgrounded mini-apps have their scan sessions immediately halted via implicit `BluetoothLEScan.stop()`.
- **Anti-Tracking & MAC Address Shielding**: Physical 48-bit IEEE MAC addresses are strictly shielded from mini-app scripts. The container generates ephemeral `device.id` identifiers using an HMAC keyed with a per-mini-app secret salt, preventing cross-app tracking.

### 2. W3C MediaCapture Image API: High-Resolution Optical Governance
Standardizes hardware-level still capture and computer vision frame acquisition bound to an active `MediaStreamTrack`.
- **Decoupled Optical Pipeline**: Unlike capturing frames from `<video>` tags via `<canvas>` (which is constrained to preview video resolutions like 720p/1080p), `ImageCapture` accesses the native camera sensor pipeline, enabling full-resolution captures up to 48MP/108MP.
- **Still Photo Capture (`takePhoto()`)**: Accepts `photoSettings` (`imageWidth`, `imageHeight`, `fillLightMode: 'off'|'auto'|'flash'`). Returns an encoded `Blob` (`image/jpeg` or `image/png`). The super-app enforces a minimum memory threshold (>=150MB free RAM) to prevent Out-Of-Memory termination, strips GPS/hardware serial EXIF tags by default, and plays mandatory shutter audio where required by law.
- **Zero-Copy Stream Extraction (`grabFrame()`)**: Captures immediate uncompressed GPU/CPU memory snapshots resolving to `ImageBitmap`. These can be transferred zero-copy to Dedicated Web Workers via `Transferable` handles, executing client-side barcode scanning, OCR, or face detection at up to 30 fps without blocking the main UI thread. Developers must explicitly invoke `imageBitmap.close()` to prevent memory leaks.
- **Hardware Limits (`getPhotoCapabilities()`)**: Queries physical optical ranges (`MediaSettingsRange` for zoom, exposure compensation, ISO, and color temperature) to validate requested constraints before dispatching native camera commands.
- **Super-App Optical eKYC Security**: Mandates minimum 1080p resolution for identity card scanning, native viewfinder stencils with real-time blur detection, and in-memory WebCrypto AES-GCM-256 encryption of document photos before network transit.

### 3. FIDO2 / WebAuthn Passkeys Architecture: Multi-Device Cryptographic Identity
Establishes passwordless, phishing-resistant authentication across desktop, mobile, and web surfaces.
- **Multi-Device Synchronized Credentials**: Passkeys operate as discoverable resident keys whose private keys are generated within hardware cryptographic modules and synchronized across user devices via end-to-end encrypted cloud keychains (Apple iCloud Keychain, Google Password Manager).
- **Cryptographic Origin Binding**: Authenticator assertions sign over a SHA-256 hash of `clientDataJSON` (`type`, `challenge`, `origin`, `crossOrigin`) and `authData`. The Relying Party ID (`rp.id`) must strictly match the caller's origin, mathematically thwarting phishing and reverse-proxy credential interception.
- **FIDO CTAP 2.0/2.1 Protocol**: Details client-to-authenticator communication over CBOR. User verification is secured using the `pinUvAuthToken` protocol: ephemeral ECDH key exchange establishes a shared secret, enabling authentication commands without exposing raw user PINs or biometric templates to the host platform.
- **Passkey Conditional UI**: Integrates passkey selection into browser autofill dropdowns via `mediation: conditional` and HTML `<input autocomplete="username webauthn">`. Eliminates intrusive modal prompts while enabling one-tap biometric login.
- **Super-App Multi-Tenant Delegation**: Overcomes the WebAuthn single-origin restriction in multi-tenant super-apps. The super-app root origin authenticates the user as the primary Relying Party, then issues down-scoped, audience-restricted OAuth/OIDC JWT tokens to third-party merchant mini-apps via token exchange.
