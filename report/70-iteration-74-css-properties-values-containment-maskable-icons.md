# Chuyên đề 70: W3C CSS Properties and Values API Level 1 (@property), W3C CSS Containment Level 2 (content-visibility) & W3C Web App Manifest Maskable Icons

## 1. Tóm tắt điều hành & Bối cảnh kỹ thuật

Trong kiến trúc Super App hiện đại, mini-app chạy trong môi trường WebView phân mảnh với sự pha trộn giữa giao diện gốc của ứng dụng mẹ (Host Capsule Chrome, Navigation Bars) và mã nguồn giao diện động từ các đối tác thứ ba (Guest Mini-Apps). Ba bài toán kỹ thuật cốt lõi quyết định tính toàn vẹn thương hiệu, hiệu năng hiển thị danh mục lớn và an toàn định dạng giao diện gồm:

1. **An toàn kiểu dữ liệu và tối ưu hiệu ứng CSS (CSS Properties & Values API Level 1 / @property)**: Trước đây, các biến CSS (CSS Custom Properties) chỉ là các luồng token chuỗi không xác định kiểu (`*`), không thể kiểm tra cú pháp và không thể nội suy (interpolate) chuyển động mượt mà bằng phần cứng GPU (thường bị giật khung hình ở 50%). Chuẩn W3C CSS Properties and Values API Level 1 cung cấp quy tắc `@property` và phương thức `CSS.registerProperty()`, cho phép định nghĩa kiểu dữ liệu chặt chẽ (`<color>`, `<length>`, `<percentage>`, `<integer>`), gán giá trị mặc định bảo đảm (`initial-value`) và kiểm soát lan truyền (`inherits: false`). Cơ chế này giúp Super App chia sẻ các Design Token an toàn, ngăn chặn CSS Injection và kích hoạt hoạt ảnh 120fps mượt mà trực tiếp trên luồng GPU Compositor mà không gây nghẽn luồng JavaScript chính.
2. **Tối ưu hóa hiển thị danh mục lớn & tiết kiệm RAM (CSS Containment Module Level 2 / content-visibility)**: Các mini-app thương mại điện tử, đặt phòng và cổng tin tức thường render danh sách hàng trăm sản phẩm khiến cây DOM phình to, làm sụt giảm nghiêm trọng chỉ số First Contentful Paint (FCP) và Time to Interactive (TTI), đồng thời tiêu tốn hàng trăm MB RAM gây lỗi crash do Android Low Memory Killer (LMK). Thuộc tính `content-visibility: auto` kích hoạt đồng thời layout, style và paint containment, chỉ thị cho trình duyệt bỏ qua (skip) toàn bộ công đoạn tính toán bố cục và vẽ đồ họa của các phần tử nằm ngoài khung nhìn (off-screen) cho đến khi người dùng cuộn tới. Kết hợp với `contain-intrinsic-size` để triệt tiêu hiện tượng nhảy thanh cuộn và loại bỏ lỗi Cumulative Layout Shift (CLS < 0.1), giải pháp này giúp tăng tốc độ tải trang ban đầu gấp 5–10 lần mà vẫn bảo toàn đầy đủ cây trợ năng (Accessibility Tree / AOM) và tính năng tìm kiếm nội dung (Find-in-Page).
3. **Chuẩn hóa biểu tượng thích ứng đa nền tảng (Web App Manifest Maskable Icons & Safe Zone Geometry)**: Trên các bệ phóng ứng dụng di động (OS Launchers như Android Pixel, Samsung OneUI, iOS), biểu tượng ứng dụng bị cắt theo nhiều hình dạng khác nhau (tròn, squircle, giọt nước, lục giác). Biểu tượng truyền thống (`purpose: any`) có nền trong suốt thường bị đóng khung trắng xấu xí (white letterboxing) hoặc bị cắt mất viền logo thương hiệu. Chuẩn W3C Web App Manifest định nghĩa `purpose: "maskable"` và chuẩn hóa "Vùng an toàn" (Safe Zone) hình tròn đồng tâm có bán kính bằng 2/5 (40%) kích thước biểu tượng (đường kính 80%). Toàn bộ biểu trưng cốt lõi phải nằm trọn trong vùng an toàn 80%, trong khi phần viền 10% bên ngoài là phần nền tràn viền (full-bleed) có thể bị cắt gọt tùy ý mà không làm tổn hại hình ảnh đối tác.

Milestone 74 chuẩn hóa chi tiết 15 phát hiện kỹ thuật trên cả 3 miền công nghệ này, làm căn cứ kiểm thử tự động và thiết lập rào chắn tiêu chuẩn kỹ thuật (Store Quality Gate) cho nền tảng Super App.

### [css_prop_074_01] W3C CSS @property Rule: Declarative Custom Property Registration & Type-Safe Parsing
- **Chủ đề**: `at_property_rule_syntax_and_type_checking`
- **Phân loại**: Interoperability, Offline & Runtime Architecture | **Mức độ chứng cứ**: specification
- **Tiêu chuẩn tham chiếu**: W3C CSS Properties and Values API Level 1 §3 The @property Rule
- **URL chính thức**: [https://www.w3.org/TR/css-properties-values-api-1/](https://www.w3.org/TR/css-properties-values-api-1/)
- **URL hỗ trợ**: [https://developer.mozilla.org/en-US/docs/Web/CSS/@property](https://developer.mozilla.org/en-US/docs/Web/CSS/@property), [https://developer.mozilla.org/en-US/docs/Web/API/CSS/registerProperty_static](https://developer.mozilla.org/en-US/docs/Web/API/CSS/registerProperty_static)
- **Tóm tắt cốt lõi**: The @property rule enables declarative registration of CSS custom properties with strict type definitions, initial values, and inheritance controls, eliminating parse-time ambiguity and silent styling failures.
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] W3C CSS Properties and Values API Level 1 §3 defines the '@property' at-rule, allowing developers to register custom properties directly within CSS stylesheets without requiring JavaScript execution. A valid @property descriptor requires 'syntax' (defining expected data types such as '<color>', '<length>', '<percentage>', '<integer>', or composite types) and 'inherits' (a boolean determining whether values cascade down the DOM subtree). The 'initial-value' descriptor is mandatory for all syntaxes except the universal wildcard ('*'). If required descriptors are missing or fail parsing, the user agent must discard the entire @property rule. Unlike standard unregistered CSS variables (which default to token streams evaluated as arbitrary strings), registered custom properties undergo type validation at computed-value time. [SUPERAPP ARCHITECTURE] Super-app host platforms expose branded design tokens (e.g., '--host-brand-color', '--host-nav-height', '--host-safe-area-top') to embedded mini-apps. By defining these tokens via '@property', the host enforces type safety (e.g., ensuring '--host-brand-color' only accepts valid '<color>' values). If a mini-app attempts to inject invalid CSS values or script strings into host custom properties, the user agent automatically rejects the malformed value and falls back to the guaranteed 'initial-value', preventing cross-component UI breakage and styling pollution.

- **Tiêu chuẩn tham chiếu**: W3C CSS Properties and Values API Level 1 §4 Registering Custom Properties in JS

- **Tóm tắt cốt lõi**: CSS.registerProperty() provides a programmatic interface for registering typed custom properties, throwing an InvalidModificationError if a property is re-registered with conflicting parameters.
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] W3C CSS Properties and Values API Level 1 §4 defines 'window.CSS.registerProperty(definition)', extending the global CSS object. The PropertyDefinition dictionary takes 'name' (a valid CSS custom property identifier starting with '--'), 'syntax' (defaulting to '*'), 'inherits' (boolean), and 'initialValue' (must be computationally independent and parseable according to the declared syntax). If 'registerProperty()' is called with a name that already exists within the document's [[registeredPropertySet]], the browser throws an 'InvalidModificationError' DOMException. Furthermore, if the initial value is not computationally independent (for example, attempting to define 'initialValue: 3em' which depends on ambient font-size), the method immediately throws a 'SyntaxError'. [SUPERAPP ARCHITECTURE] When the super-app container initializes a mini-app runtime environment, the host kernel invokes 'CSS.registerProperty()' during early bootstrap to lock in foundational layout and theming tokens before third-party mini-app code executes. Because re-registration throws an 'InvalidModificationError', rogue mini-app scripts cannot overwrite or alter the inheritance or syntax rules established by the host platform, creating an immutable styling boundary between host UI and untrusted guest code.

- **Tóm tắt cốt lõi**: Setting 'inherits: false' stops CSS custom properties from cascading down the DOM tree, establishing strict style encapsulation for embedded components and third-party widgets.
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] In standard CSS, custom properties inherit by default across all descendant elements. This cascading behavior can cause unintended side effects where a parent container's variable overrides or corrupts child component styling. W3C CSS Properties and Values API Level 1 §3.2 provides the 'inherits' descriptor. When set to 'false', the registered custom property behaves like non-inheriting native CSS properties (e.g., 'border' or 'background'): it applies exclusively to the targeted selector and does not cascade to child DOM nodes unless explicitly assigned or re-declared. Descendants automatically receive the property's declared 'initial-value'. [SUPERAPP ARCHITECTURE] In super-app architectures featuring multi-tenant mini-apps or embedded third-party widgets (e.g., payment keypad sheets, mini-program promotional banners, loyalty cards), setting 'inherits: false' prevents host-level variables from leaking into and unintentionally mutating guest component layouts. Conversely, it ensures that mini-app stylesheets cannot redefine variables that cascade into and break super-app security capsule controls or bottom navigation bars.

### [contain_074_01] W3C CSS content-visibility: auto: Rendering Omission & Massive Layout/Paint Optimization
- **Chủ đề**: `content_visibility_auto_and_rendering_omission`
- **Phân loại**: Interoperability, Offline & Runtime Architecture | **Mức độ chứng cứ**: specification
- **Tiêu chuẩn tham chiếu**: W3C CSS Containment Module Level 2 §5.1 content-visibility property
- **URL chính thức**: [https://www.w3.org/TR/css-contain-2/](https://www.w3.org/TR/css-contain-2/)
- **URL hỗ trợ**: [https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility), [https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size)
- **Tóm tắt cốt lõi**: Applying 'content-visibility: auto' turns on layout, style, and paint containment, instructing the browser to skip layout and painting of off-screen elements until they approach the viewport.
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] W3C CSS Containment Module Level 2 §5.1 defines 'content-visibility: visible | hidden | auto'. Setting 'content-visibility: auto' instructs the browser to activate layout containment, style containment, and paint containment on the element. If the element is determined to be non-relevant to the user (i.e. outside the visual viewport plus an implementation margin), the user agent skips the rendering work of the element's subtree entirely, omitting style recalculation, layout generation, and GPU painting. This yields massive initial page load speedups (often 5x to 10x faster rendering for long documents) and drastic memory reductions. Unlike 'display: none', the element remains in the DOM tree, preserves its CSS computed style, and remains searchable. [SUPERAPP ARCHITECTURE] Super-app mini-apps displaying deep catalogs, multi-store shopping feeds, or lengthy transaction histories apply 'content-visibility: auto' to off-screen list items and product cards. This optimization drastically slashes First Contentful Paint (FCP) and Time to Interactive (TTI) on entry-level Android devices, ensuring that mini-apps with hundreds of DOM nodes initialize with sub-second responsiveness without requiring fragile manual DOM-node recycling scripts.

### [contain_074_02] contain-intrinsic-size: Placeholder Geometry & Cumulative Layout Shift (CLS) Defense
- **Chủ đề**: `contain_intrinsic_size_and_cls_elimination`
- **Phân loại**: Interoperability, Offline & Runtime Architecture | **Mức độ chứng cứ**: specification
- **Tiêu chuẩn tham chiếu**: W3C CSS Containment Module Level 2 §5.2 contain-intrinsic-size property
- **URL chính thức**: [https://www.w3.org/TR/css-contain-2/](https://www.w3.org/TR/css-contain-2/)
- **URL hỗ trợ**: [https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size), [https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility)
- **Tóm tắt cốt lõi**: contain-intrinsic-size specifies placeholder dimensions for elements with skipped contents, preventing scrollbar jumping and eliminating Cumulative Layout Shift (CLS).
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] When an element's contents are skipped via 'content-visibility: auto', the browser treats the element as if it has no child contents, collapsing its height to 0 unless an explicit dimension is provided. This collapse causes scrollbar instability, erratic jumping, and catastrophic Cumulative Layout Shift (CLS). W3C CSS Containment Level 2 introduces 'contain-intrinsic-size', allowing authors to declare explicit placeholder dimensions (e.g. 'contain-intrinsic-size: auto 300px'). With the 'auto <length>' syntax, once the element scrolls into view and its true contents are rendered, the browser caches the real rendered intrinsic size in memory and reuses it if the element later scrolls off-screen, completely preserving scroll position and layout stability throughout long browsing sessions. [SUPERAPP ARCHITECTURE] Super-app mini-app store review guidelines enforce strict Core Web Vitals thresholds (mandating Cumulative Layout Shift / CLS < 0.1). Mini-apps utilizing 'content-visibility: auto' on dynamic product grids or news feeds MUST declare 'contain-intrinsic-size: auto 250px'. Store compliance audit bots test scroll stability across synthetic viewports; mini-apps that cause scrollbar jumpiness or layout shifts due to missing intrinsic sizes are flagged for automated remediation.

### [contain_074_03] contentvisibilityautostatechange Event: Pausing Heavy Background Processes & Canvases
- **Chủ đề**: `contentvisibilityautostatechange_event_lifecycle`
- **Phân loại**: Interoperability, Offline & Runtime Architecture | **Mức độ chứng cứ**: specification
- **Tiêu chuẩn tham chiếu**: W3C CSS Containment Module Level 2 §5.3 The contentvisibilityautostatechange Event
- **URL chính thức**: [https://www.w3.org/TR/css-contain-2/](https://www.w3.org/TR/css-contain-2/)
- **URL hỗ trợ**: [https://developer.mozilla.org/en-US/docs/Web/API/Element/contentvisibilityautostatechange_event](https://developer.mozilla.org/en-US/docs/Web/API/Element/contentvisibilityautostatechange_event), [https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility)
- **Tóm tắt cốt lõi**: The contentvisibilityautostatechange event fires when an element enters or leaves the skipped rendering state, allowing scripts to stop/start canvas loops, video decoding, and network polling.
- **Phân tích kỹ thuật & Kiến trúc Super App**:
  [SPEC FACT] W3C CSS Containment Level 2 defines the 'contentvisibilityautostatechange' event, which fires on any element configured with 'content-visibility: auto' whenever the user agent starts or stops skipping its rendering work. The event provides a boolean 'skipped' property: 'skipped === true' indicates that the element has left the viewport and its subtree rendering is now omitted, while 'skipped === false' signals that the element is approaching the viewport and rendering has resumed. This event provides a standard, high-efficiency mechanism for JavaScript to pause expensive non-rendering tasks (such as requestAnimationFrame loops, WebGL canvas shaders, video element streams, or polling timers) without needing multiple IntersectionObserver instances. [SUPERAPP ARCHITECTURE] High-performance mini-apps (such as financial charts, real-time trading dashboards, and interactive mini-games) listen to 'contentvisibilityautostatechange'. When a chart widget is skipped, the mini-app immediately suspends high-frequency WebSocket data decoding and stops Canvas 2D render loops. When the user scrolls the chart back into view ('skipped === false'), the widget re-subscribes and repaints, conserving mobile battery, reducing CPU thermal throttling, and preventing out-of-memory crashes.

## 4. Khuyến nghị Kiến trúc & Tiêu chuẩn cho Super App Store Gate

1. **Host Design Token Protection qua `@property`**:
   - Host Super App bắt buộc khai báo toàn bộ token giao diện (màu sắc, chiều cao thanh điều hướng, kích thước safe area) bằng cú pháp `@property` hoặc `CSS.registerProperty()` với kiểu cụ thể (`<color>`, `<length>`) và `inherits: false`.
   - Cấm mini-app ghi đè các biến thuộc namespace `--host-*` hoặc `--superapp-*`. Trình duyệt tự động loại bỏ giá trị không hợp lệ và khôi phục `initial-value`.

2. **Quy tắc Kiểm thử Hiệu năng Danh mục & CSS Containment**:
   - Mọi mini-app chứa danh sách sản phẩm hoặc bảng tin dài trên 50 phần tử bắt buộc áp dụng `content-visibility: auto` kết hợp `contain-intrinsic-size: auto 250px`.
   - Store Review Gate tự động quét cây DOM và đo lường chỉ số CLS trong quá trình cuộn tự động (synthetic scroll test). Nếu CLS >= 0.1 do thiếu `contain-intrinsic-size`, hệ thống từ chối duyệt phiên bản (Blocker Issue).
   - Tận dụng sự kiện `contentvisibilityautostatechange` để tự động ngắt kết nối WebSocket/Canvas của các widget tài chính/biểu đồ khi cuộn ra ngoài khung nhìn nhằm tiết kiệm pin thiết bị.

3. **Tiêu chuẩn Biểu tượng Thích ứng Mini-App (Adaptive Icon Gate)**:
   - Gói mini-app bắt buộc cung cấp ít nhất một biểu tượng `512x512` có khai báo `purpose: "any maskable"`, không chứa pixel trong suốt (`alpha == 1.0` toàn bộ viền ngoài).
   - Toàn bộ nội dung nhận diện thương hiệu phải nằm trong Vùng an toàn hình tròn bán kính 40% (80% đường kính).
   - Bot kiểm duyệt tự động kiểm tra tỷ lệ tương phản luminance đạt tối thiểu 3:1 trên cả nền sáng (#FFF) và nền tối (#121212), đảm bảo trải nghiệm thẩm mỹ cao cấp nhất quán trên toàn hệ sinh thái Super App.
